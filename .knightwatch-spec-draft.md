# `.knightwatch/` per-repo config — spec

**Status:** spec for next PR
**Motivator:** bot Finding 1 on PR #28 ("per-base allowlist drift") — `SOURCE_PATHS` today applies globally; reviewing a `cncorp/plow` PR exposes ALL configured siblings (including `srosro/tkmx-server`, `srosro/vibe-engineering`, etc.) when only `cncorp/plow-content` is actually relevant.

## Goal

Move per-repo declarations (sibling-grep allowlist, product context, dead-code command, strict-typing command) OUT of central `repos.conf` + `~/.pr-reviewer/contexts/` and INTO each tracked repo's own `.knightwatch/` directory. Each repo's owners control what cross-repo signals their PRs get; the operator's `repos.conf` shrinks to "which repos to watch + where their checkouts live on disk."

## Schema

`.knightwatch/` is a directory at the repo root containing **one file per concern**. No central manifest, no parser dependency — each file's format is what's natural for its concern. Reading is `git show origin/<default-branch>:.knightwatch/<file>`.

Initial v1 ships exactly 4 files (each optional — absence falls back to today's behavior):

```
.knightwatch/
  siblings                # one repo-slug per line, # comments allowed
  product-context.md      # markdown blob, replaces ~/.pr-reviewer/contexts/<slug>.md
  dead-code.sh            # bash one-liner/script, replaces DEAD_CODE_CMDS[<slug>]
  strict-typing.sh        # bash one-liner/script, replaces STRICT_TYPING_CHECKS[<slug>]
```

### `.knightwatch/siblings`

```
# Sibling repos that are "in scope" for cross-repo grep when reviewing
# PRs on THIS repo. Slugs match repos.conf entries; operator must have
# the checkout configured in SOURCE_PATHS.
cncorp/plow-content
```

Empty file (or absent) = no siblings (same-repo-only review).

### `.knightwatch/product-context.md`

Plain markdown blob — same content shape as today's `~/.pr-reviewer/contexts/<slug>.md`. Read by all specialists; informs intent inference. No schema imposed.

### `.knightwatch/dead-code.sh`

A bash command line. Run by the worker as `bash -c "$content" -- "$@"` with cwd = the PR's per-PR workdir, touched-file paths passed as positional args. Same contract as the existing `DEAD_CODE_CMDS[<slug>]` value — relocated, not redesigned.

Empty file (or absent) = no static dead-code tool (LLM grep still runs from the diff).

### `.knightwatch/strict-typing.sh`

Same contract as `STRICT_TYPING_CHECKS[<slug>]` — a bash command, tri-state via exit code (loud-on-failure). Relocated, not redesigned.

## Trust model

**Read from the base branch only, never PR head.** A PR can't grant itself new sibling exposure or change the product-context framing by editing its own `.knightwatch/` files in head commits. Worker reads each file via:

```bash
git -C "$REPO_DIR" show "origin/${DEFAULT_BRANCH}:.knightwatch/<file>" 2>/dev/null
```

Empty / non-existent file (or git-show failure) = use the fallback (current `repos.conf` / `~/.pr-reviewer/contexts/` value).

**Implication:** to add a sibling to the allowlist, a committer files a PR that adds the slug to `.knightwatch/siblings` on the base branch. That PR is itself reviewed under the OLD policy. After merge, subsequent PRs use the new policy. Same for product context and dead-code/strict-typing commands.

**dead-code.sh and strict-typing.sh execute arbitrary shell on the reviewer host.** This is the same trust boundary as today's `DEAD_CODE_CMDS` / `STRICT_TYPING_CHECKS` (operator chooses what to run). Moving from `repos.conf` to base-branch-only `.knightwatch/` doesn't widen this — only people who can land code on main can edit the script content, same as today.

## What stays in `repos.conf`

Only operator-side concerns:

```bash
# Which repos to watch
REPOS=("cncorp/plow" "cncorp/plow-content" ...)

# Where each repo's checkout lives on this host (operator's filesystem layout)
declare -A SOURCE_PATHS=(...)

# KID index paths — same idea, operator's filesystem
declare -A KID_PATHS=(...)
```

Removed (moved into per-repo `.knightwatch/`):
- `DEAD_CODE_CMDS` → `.knightwatch/dead-code.sh`
- `STRICT_TYPING_CHECKS` → `.knightwatch/strict-typing.sh`

(`~/.pr-reviewer/contexts/<slug>.md` files become obsolete once the per-repo `.knightwatch/product-context.md` lands; can be deleted by the operator after migration.)

## Worker-side changes

New helper file `lib/knightwatch-config.sh`:

```bash
# read_knightwatch_file <repo_dir> <default_branch> <relative_path>
#   stdout: file content from origin/<default_branch>:.knightwatch/<relative_path>
#   exit:   0 if file exists and was read; 1 otherwise (caller falls back)
read_knightwatch_file() {
    local repo_dir="$1" default_branch="$2" rel_path="$3"
    git -C "$repo_dir" show "origin/${default_branch}:.knightwatch/${rel_path}" 2>/dev/null
}
```

Three callers in `lib/review-one-pr.sh` and one in `lib/search-roots.sh`:
- `stage_search_roots`: read `siblings` → use as the allowlist; fall back to "all SOURCE_PATHS slugs except self"
- product-context loader: read `product-context.md` → fall back to `~/.pr-reviewer/contexts/<slug>.md`
- dead-code-cmd loader: read `dead-code.sh` → fall back to `DEAD_CODE_CMDS[<slug>]`
- strict-typing-cmd loader: read `strict-typing.sh` → fall back to `STRICT_TYPING_CHECKS[<slug>]`

Each fallback is preserved in this PR for backwards-compat. Once all 6 tracked repos have `.knightwatch/` files committed on their main branches, the fallbacks can be removed in a follow-up.

## Backwards-compat / migration

Three onboarding states a repo can be in:

1. **No `.knightwatch/`** — current behavior preserved via fallback to `repos.conf` entries (`SOURCE_PATHS`-derived sibling list, `~/.pr-reviewer/contexts/<slug>.md`, `DEAD_CODE_CMDS[<slug>]`, `STRICT_TYPING_CHECKS[<slug>]`). No regression for un-onboarded repos.
2. **`.knightwatch/` partially populated** — each file is independent. A repo with only `.knightwatch/siblings` uses the new sibling allowlist + falls back to current `repos.conf` entries for the others.
3. **`.knightwatch/` fully populated** — worker uses it for everything; `repos.conf` entries for that repo are unused (kept for backwards-compat until a follow-up removal PR).

Migration is opt-in per repo: as each repo's owners want finer control, they commit `.knightwatch/` to their main branch.

## Test plan

- New smoke `lib/tests/knightwatch-config-smoke.sh`:
  - read existing file → returns content + exit 0
  - read missing file → returns empty + exit 1
  - read from a non-base-branch ref (PR head) → returns base-branch content (proves trust model)
- Updated `lib/tests/search-roots-smoke.sh`:
  - `.knightwatch/siblings` present → uses that allowlist
  - `.knightwatch/siblings` absent → falls back to "all SOURCE_PATHS minus self"
- E2E: drop `.knightwatch/siblings` containing only `cncorp/plow-content` into `~/Hacking/plow/.knightwatch/`, commit on main, trigger a /srosro-review on a `cncorp/plow` PR → verify the search-roots output for that PR includes only plow-content as a sibling, not the srosro/* repos.

## Out of scope for v1

- Per-PR `.knightwatch/` overrides
- Specialist-prompt augmentation per repo
- Anything that requires reading the PR head (trust model forbids)
- Removal of `repos.conf` fallback entries (deferred until all repos have `.knightwatch/` committed)
